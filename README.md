# PIA厚木（本厚木）データビューアー

## GitHub Pages（サーバー不要）

GitHub Actionsが5分おきに更新を確認し、変更があればPagesへ公開します。履歴の再取得は6時間ごと（Actionsの手動実行なら即時）です。ページは表示中、毎分データを確認します。GitHub Actionsの最短スケジュールは5分間隔なので、厳密な毎分のデータ取得ではありません。履歴DBと公開ページをリポジトリで管理するため、常時稼働サーバーやPCは不要です。Actionsの初回実行は「Actions」から `Refresh and publish PIA Atsugi viewer` を選び、`Run workflow` を実行してください。Pages公開設定が未設定の場合は、Repository settings → Pages → Build and deployment → GitHub Actions を選びます。

公開用ファイルは `python generate_static.py` で `docs/` に生成します。GitHub Actionsでは毎晩同じ生成処理を行い、データに変更があればコミットしてからPagesへ公開します。自動更新はActionsが有効であることが条件です。

## ローカルサーバー版

`python app.py` で起動し、 http://localhost:5000 を開きます。既存の起動バッチも利用できます。

- 表示する店舗はPIA厚木（本厚木、公式店舗ID14）のみです。
- 設置台は公式APIから取得します。APIはフォーム送信を要求するため、JSON送信で別店舗へフォールバックする旧実装を修正しています。
- 公開されている台番号別の過去実績を自動取得し、完了した日付の履歴を集計します。分析期間は7・14・30・90・180・365日です。取得できた古い実績も元の日付のままDBへ保存します。
- 同一機種・同一レートの実績を比較し、差枚・差玉、プラス日数、回転数、直近の実績から参考順位を付けます。各台3日以上、規定回転数以上と比較可能な他台が必要です。履歴不足や入替後の台は候補にしません。
- 公開取材データは掲載日・掲載台が限定されています。全台・全営業日の収支を表すデータではなく、参考スコアは将来の当選確率を表しません。取得元・収録状況は画面に表示します。
- 公式の設置情報と公開ランキングも取得時刻を添えて `data/daily/YYYY-MM-DD.official.json.gz` に保存します。ランキングは同じ台の複数記録を含み、対象営業日が提供されていないため、取得日を実績日として日別分析に混ぜません。公式の会員向け日別履歴は未取得です。
- ローカルサーバー版は起動時にバックグラウンド収集を開始し、公開履歴を6時間ごと・失敗時は5分後に再取得します。毎日23:00（日本時間）に日付別バックアップを保存します。
- 履歴は `data/history.sqlite3` に保存します。日別の圧縮JSONは `data/daily/YYYY-MM-DD.json.gz`、直近のDB復旧コピーは `data/daily/latest.sqlite3` です。JSONの保存日と実績日は別項目として記録し、同じ日の再取得で重複しません。起動直後にも本日の途中保存を作ります。
- 最終保存・次回保存・DBにある実績の期間は画面の「サーバー保存状況」と `/api/collection` から確認できます。`/api/history?start=2021-01-01&end=2021-12-31` のように元の実績日で古い保存データを確認できます。
- サーバーやこのPCの電源が切れている間は収集できません。再起動後も保存済みの履歴を読み込み、その日の保存を再開します。電源OFF中の未取得の全台データを補完した扱いにはしません。
- 保存先は `PIA_HISTORY_DB` で変更できます。Dockerで履歴を維持する場合は名前付きボリュームなどを `/app/data` に接続してください。Gunicornは付属設定の `post_worker_init` から収集を開始します。

検証: `python -m unittest discover -v`、`node --check static/viewer.js`。
